## Highlights

The Remote Control session experience gets a real upgrade this release. A dedicated session menu lets you disconnect, regenerate a pairing QR code, and delete sessions cleanly. Slash commands can now be dispatched from a paired device, with local-only commands kept local. AI-generated session titles finally persist across reloads and `/rename`. A few long-standing bugs in the history replay, conversation export, and client handoff are also fixed.

### New Features

- **Active session menu in Remote Control** — A new menu for managing a live Remote Control session: disconnect, show the pairing QR code again, or hard-delete the session entirely. The pairing flow also handles resuming an existing session alongside creating a new one, so reconnecting feels the same as pairing for the first time.

- **Slash commands work over Remote Control** — You can now run slash commands from a paired phone or browser. Each command runs on the CLI and the output is forwarded back to the remote client. Commands that are inherently local-only (login, logout, exit, add-dir, remote-control itself) stay local and don't show up in the remote picker, so the remote surface stays focused on commands that make sense from a phone. Plugin reload and skill refresh commands are routed through to the paired device.

- **AI-generated session titles persist** — When the CLI suggests a title at the end of your first turn, that title is now saved and survives across reloads and device switches.

### Bug Fixes

- **History buffer could be replayed more than once on a fast reconnect** — On a quick same-tick reconnect or a client swap, the conversation history could be re-sent to the paired device, leading to duplicate frames at the top of the transcript. The replay now fires exactly once per bridge instance.

- **Stale model and permission mode after a client swap** — When a paired device swapped out (e.g. switching phones), the new client used to show the previous device's model and permission mode until something else changed locally. The new device now picks up the current state immediately on connect.

- **Empty conversations no longer export to a blank file** — Exporting a conversation with no messages now shows a clear message instead of silently writing an empty file.

- **API-key verification status could be clobbered** — A second verification check could overwrite a prior "verified" status back to "checking," causing the CLI to flicker between states. The verification status is now stable.
