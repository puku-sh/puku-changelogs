## Highlights

Self-update is no longer tied to a package manager — the bundled binary now updates itself in place. The permission layer also gets a small fix so reads and writes under `/tmp` work consistently across every entry point.

### New Features

- **In-place self-update from the bundled binary** — The standalone `puku-cli` binary now checks for and applies updates on its own (no `apt` / `brew` / `npm` step in the loop). The install script and the in-app update flow both reach the same updater path, so `puku-cli update` either finishes the job or hands you a clear error explaining what went wrong.

### Bug Fixes

- **`/tmp` reads and writes now use the same carve-out everywhere** — Earlier releases allowed writes inside `/tmp` at the tool boundary but rejected the same paths inside the inner permission checks, so a redirect like `echo '...' > /tmp/x.js` would prompt unexpectedly. Both flows now share the same exception, and `/tmp/.ssh` (and any other explicit deny) still blocks first.
- **`/doctor` no longer stalls the bundled binary** — On some machines the diagnostic step inside a wedged install would hang before producing output. The bundled binary now has a hard ceiling on the diagnostic step and falls back gracefully.
- **Bundled-binary detection no longer misroutes the update path** — A signal in the Bun-compiled binary's argv is now what tells the updater "you're the bundled binary; talk to R2, don't pretend to be a package-managed install." This was occasionally sending the updater down the wrong branch and producing confusing errors.
