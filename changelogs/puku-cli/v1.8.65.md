## Highlights

A broad release that touches the install flow, login reliability, and a couple of permission edge cases. The installer now plays nicely with all major Linux package managers (and knows when to back off and let them handle `PATH` themselves), PKCE logins refresh automatically when your token expires, and there's a new `/feedback` slash command for reporting issues.

### New Features

- **`/feedback` slash command** — A new slash command lets you send structured issue reports to the public issue tracker without leaving the CLI. It's intended as the primary "I hit something weird" path going forward.
- **Automatic PKCE session refresh on 401** — If you're signed in with PKCE and the server returns a 401, the CLI now transparently refreshes the session and retries the call. Subagents recover from expired tokens on their own; you don't see anything unless the refresh itself fails.
- **Tighter installer behavior with package-manager installs** — The `curl | bash` installer now detects when `puku-cli` is already installed via `apt` / `rpm` / `pacman` / `apk` / Homebrew and steps out of the way, instead of double-mutating your shell rc files or racing with the package manager's own profile scripts.
- **Better PATH coverage for fresh installs** — When you install Puku CLI via the shell installer, your `~/.local/bin` (or your `$XDG_USER_BIN`) is now added to `PATH` in your shell rc file if it isn't already, with the same sentinel the in-app `/install` slash command uses, so re-running either path is safe.
- **`/uninstall` slash command with `--purge-config`** — A new in-app `/uninstall` command removes the binary and (with `--purge-config`) wipes your `~/.puku/` directory as well. The shell installer gained a matching `uninstall` mode.

### Bug Fixes

- **`/tmp` reads and writes use the same carve-out across every flow** — The exception that lets you read and write under `/tmp` (so e.g. `echo '...' > /tmp/x.js` doesn't get blocked) now lives in one place and is honored by every permission flow. Explicit deny rules (such as `/tmp/.ssh`) still take precedence. This was the same shape as the v1.8.57 fix but tightened to cover a few more code paths.
- **Auto-classifier doesn't over-trigger on heredoc bodies** — When the LLM-based autopilot classifier is enabled, it used to interpret literal text inside heredoc bodies (e.g. PR descriptions passed to `gh pr create --body`) as destructive intent and refuse the command. Heredoc bodies are now redacted before the classifier sees them, so the classifier can focus on the actual shell commands. The classifier is still off by default; this only affects users who have explicitly turned it on.
- **Installer respects XDG paths** — The installer now resolves `~/.local/share`, `~/.local/state`, and `~/.local/bin` through `$XDG_*_HOME` (the same way the runtime does), so users who have relocated those directories get a consistent install.
- **`puku-cli update` after `install.sh` works again** — Several related fixes in the auto-updater and the installer writeback path mean a successful `install.sh` run no longer confuses the next `puku-cli update` call. The runtime now sees the install as soon as `/install` (or `install.sh`) finishes.
