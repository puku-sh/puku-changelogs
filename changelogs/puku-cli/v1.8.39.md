## Highlights

This release focuses on remote-control reliability and the migration of the Remote Web UI to its new home at `puku.sh/code`. The relay transport now handles session supersession cleanly, keeps idle WebSockets alive, and surfaces concurrency-limit errors with the right code. A new active-session popup and `PukuRelayIndicator` round out the in-CLI session experience, and the bridge now extracts inline image blocks to disk so they survive the prompt queue.

### New Features

- **Remote Web UI migrated to `puku.sh/code`** — The Remote Web UI now lives at `puku.sh/code/<sessionId>` instead of the legacy `puku-cli-web` host. The relay client and session URL builder were updated to use the new web origin, mobile/account tokens are no longer embedded in the URL query string, and the relevant components/SDK were ported over with Tailwind styling.

- **Active session popup (`PukuRelayPopup`)** — A new popup surfaces live relay session details and management actions. Added a new `remoteRelayIndicator:open` keybinding to launch the popup, plus a `closeSession` relay client call so users can end an active session from the UI.

- **`PukuRelayIndicator` component** — New footer pill that shows relay pairing state with color-coded connection status, with tests covering rendering and keybinding behavior.

- **Heartbeat for relay WebSocket transport** — The relay transport now sends periodic heartbeats to prevent intermediate proxies from closing the WebSocket on idle.

- **Enhanced remote session handling** — `remote`/`remote-web` commands now build URLs with the relay auth token, surface richer session metadata, and show clearer messaging around session state.

- **AskUserQuestion interactive permission prompts on remote bridge** — Interactive AskUserQuestion permission prompts now render on both the local CLI and the remote (mobile/web) surface, with regression tests covering the new bridge path.

### Bug Fixes

- **Bridge: inline image blocks dropped from inbound prompts** — The relay bridge was passing `ContentBlockParam` arrays straight to the prompt queue, relying on downstream resize/preserve logic that Bun's bundler was tree-shaking out of `dist/cli.mjs`. Image blocks are now extracted to disk in the bridge handler before enqueueing, so they survive the API call path.

- **Relay: handle 4002 supersede and thread `clientId` through the bridge** — When a new worker supersedes an old connection, the old transport no longer enters a reconnect flap against the still-valid worker token. The `4002` close code is now treated as terminal for this process, and `clientId` is propagated through `initPukuRelayBridge` → `useReplBridge` so the UI can show "session moved to another window" instead of silently retrying.

- **Relay: surface `concurrency_limit` error code from `createRelaySession`** — The `concurrency_limit` failure mode is no longer masked as a generic error; it now bubbles up with the correct code so callers can show a useful message.

- **Relay indicator: `remoteRelayIndicator:open` no longer fires on every Enter** — The keybinding was registered without an `isActive` gate, so it matched on every Enter keystroke while a relay session was alive, hijacking prompt submission to open the popup. The binding is now gated on `selected`, mirroring the existing footer pill pattern.
