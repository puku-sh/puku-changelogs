## Highlights

The big story this release is the auto-mode safety classifier — a behind-the-scenes gate that classifies tool calls (web fetches, web searches, shell commands) before they're executed.

### New Features

- **Auto-mode safety classifier (opt-in)** — A new opt-in safety layer that classifies tool calls before they're executed. The pipeline covers a URL blocklist for fetched content, a synthetic-traffic harness for evaluation, end-to-end tests, and a feedback surface so a denied action can come with a clear reason. The classifier is opt-in while the internal validation phase runs; the default-on flip will follow once that validation completes.

- **Trusted-repo context handling and GitHub operations templates** — The trusted-repo context surface and the permissions templates for GitHub operations are tightened, so a GitHub operations template applies without false-positive scope escalation.

- **Auto-mode opt-in dialog and feedback** — When you opt in, the dialog now spells out that an AI safety classifier is part of the loop. If the classifier denies an action, the feedback form is pre-filled with the denial context so you can quickly explain why you wanted to do it.

### Changes

- **Outbound `User-Agent` is now `Puku-User`** — For consistency across the stack and to keep upstream WAF rules happy, the outbound `User-Agent` header for auto-classifier traffic is now `Puku-User`.

- **LLM classifier behaves consistently across models** — The classifier now applies the same thinking-mode policy across all models, so you get the same behavior regardless of which pinned model is doing the classification.
