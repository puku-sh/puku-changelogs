## Highlights

When you resume a Remote Control session against a freshly-created relay (e.g. opening the paired web view for the first time after a CLI restart), the CLI is the only place the conversation history exists. Previously, a socket flap mid-batch — a reconnect, a network blip, a session-supersede racing in — could silently drop the unsent tail of the history flush forever, with no error, no retry, no signal. The flush now picks up from the snapshot boundary on the next reconnect.

### Bug Fixes

- **Conversation history replay survives socket flaps** — When a fresh Remote Control session is resuming against an empty replay ring, the conversation history flush now survives any socket flap that happens partway through. The CLI takes a snapshot of the buffered history at the start of each flush attempt, and if the transport drops frames mid-batch, only the unsent tail is re-sent on the next reconnect — never a duplicate, never a silent loss. Once an attempt completes without drops, the relay's per-session replay ring takes over and handles ordinary reconnects from there.
